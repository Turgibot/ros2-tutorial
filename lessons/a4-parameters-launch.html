A4 · Parameters and launch files

Change how a node behaves without editing its code, and start a whole group of nodes with one command.

1. Goal

So far every program had its settings written into the code: the A1 talker always sent every half second. A robot system needs the opposite. The same program must run with different settings (another arm, another speed), and starting ten nodes by hand in ten terminals does not scale. ROS 2 answers with parameters and launch files.

At the end of this lesson you will have:

  • written a node, the announcer, whose behaviour (which action it announces, and how often) is set by parameters,
  • read and changed those parameters from outside while the node runs, and set them when it starts, from the command line and from a YAML file,
  • written a launch file that starts two announcers and a listener, each with its own settings, with one command,
  • looked at the arguments of the launch file that starts the Kinova arm.

2. Concepts

Parameters

A parameter is a named, typed setting that belongs to one node. The announcer will have three:

NameTypeDefaultMeaning
namestringpickupthe symbolic action to announce
argslist of strings[A]its arguments (the blocks)
rate_hzfloat (a "double")1.0how many times per second to announce it
  • A node declares each parameter with a default value. Declaring also fixes the type: a float parameter cannot later become a string.
  • Anyone can read and change a node's parameters while it runs, with ros2 param, and the node can check a change and refuse it.
  • Values can also be given when the node starts, one by one or from a YAML file.

Why not a topic? A topic is a stream that flows all the time. A setting is different: it belongs to one node, changes rarely, must exist before the node does its first job (the default), and you want to list, read and change it by name. You will see in step 4 that, like actions in A3, parameters are built from services: every node gets get_parameters, set_parameters and so on.

Launch files

A launch file describes a group of nodes to start together: which program, under which node name, with which parameters. ros2 launch reads it, starts everything, shows all the output in one terminal, and stops everything on Ctrl+C. Launch files are Python programs that build a description (LaunchDescription); the nodes themselves can be Python or C++.

A launch file can have its own arguments, like gripper:=robotiq_2f_85 in the Kinova launch file. They are settings of the launch file itself: they decide what gets started, or what value a node gets.

Why there is a package this time ros2 run and ros2 launch only find programs that were installed by a build, as you saw for C++ in A1. So this lesson's code is one package, a4_params, that installs both the Python programs (copied as they are) and the C++ programs, plus the launch and YAML files. How a package is put together is the subject of A5.

  1. Read the announcer

    This is code/04-parameters-launch/py/announcer.py:

    #!/usr/bin/env python3
"""Publishes a symbolic action (name and arguments) as text on /action. Its settings are parameters."""
import rclpy
from rclpy.node import Node
from rcl_interfaces.msg import SetParametersResult
from std_msgs.msg import String


class Announcer(Node):
    def __init__(self):
        super().__init__('announcer')
        # Declare each parameter with a default value (this also fixes its type).
        self.declare_parameter('name', 'pickup')
        self.declare_parameter('args', ['A'])
        self.declare_parameter('rate_hz', 1.0)

        self.pub = self.create_publisher(String, 'action', 10)
        self.timer = self.create_timer(1.0 / self.get_parameter('rate_hz').value, self.tick)
        self.add_on_set_parameters_callback(self.on_change)   # called before a new value is accepted

    def on_change(self, params):
        for p in params:
            if p.name == 'rate_hz':
                if p.value <= 0.0:
                    return SetParametersResult(successful=False, reason='rate_hz must be positive')
                self.destroy_timer(self.timer)   # restart the timer with the new period
                self.timer = self.create_timer(1.0 / p.value, self.tick)
        return SetParametersResult(successful=True)

    def tick(self):
        words = [self.get_parameter('name').value] + list(self.get_parameter('args').value)
        msg = String()
        msg.data = ' '.join(words)
        self.pub.publish(msg)
        self.get_logger().info(f'sent: {msg.data}')


def main():
    rclpy.init()
    rclpy.spin(Announcer())


if __name__ == '__main__':
    main()
    • declare_parameter('name', 'pickup') creates a parameter with its default value. The default also decides the type: 1.0 makes rate_hz a float, ['A'] makes args a list of strings.
    • get_parameter('rate_hz').value reads the current value. tick reads name and args every time it runs, so changing them takes effect on the next message with no extra code.
    • add_on_set_parameters_callback(self.on_change) registers a function that is called before a new value is accepted. It returns SetParametersResult(successful=...): here a rate that is not positive is refused with a reason. An accepted new rate restarts the timer with the new period, because a timer does not notice a changed parameter by itself.

    This is code/04-parameters-launch/cpp/announcer.cpp:

    // Publishes a symbolic action (name and arguments) as text on /action. Its settings are parameters.
#include <chrono>
#include <memory>
#include <string>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

using OnSetParametersCallbackHandle = rclcpp::node_interfaces::OnSetParametersCallbackHandle;

class Announcer : public rclcpp::Node
{
public:
  Announcer() : Node("announcer")
  {
    // Declare each parameter with a default value (this also fixes its type).
    declare_parameter("name", "pickup");
    declare_parameter("args", std::vector<std::string>{"A"});
    declare_parameter("rate_hz", 1.0);

    pub_ = create_publisher<std_msgs::msg::String>("action", 10);
    start_timer(get_parameter("rate_hz").as_double());
    // Called before a new value is accepted.
    // Keep the handle in a member, or the callback is removed.
    callback_handle_ = add_on_set_parameters_callback(
      [this](const std::vector<rclcpp::Parameter> & params) {
        rcl_interfaces::msg::SetParametersResult result;
        result.successful = true;
        for (const auto & p : params) {
          if (p.get_name() == "rate_hz") {
            if (p.as_double() <= 0.0) {
              result.successful = false;
              result.reason = "rate_hz must be positive";
            } else {
              start_timer(p.as_double());   // restart with the new period
            }
          }
        }
        return result;
      });
  }

private:
  void start_timer(double rate_hz)
  {
    timer_ = create_wall_timer(
      std::chrono::duration<double>(1.0 / rate_hz), [this]() { tick(); });
  }

  void tick()
  {
    std_msgs::msg::String msg;
    msg.data = get_parameter("name").as_string();
    // Copy the list into a variable first:
    // get_parameter returns a temporary object.
    std::vector<std::string> args = get_parameter("args").as_string_array();
    for (const auto & arg : args) {
      msg.data += " " + arg;
    }
    pub_->publish(msg);
    RCLCPP_INFO(get_logger(), "sent: %s", msg.data.c_str());
  }

  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr pub_;
  rclcpp::TimerBase::SharedPtr timer_;
  OnSetParametersCallbackHandle::SharedPtr callback_handle_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<Announcer>());
  rclcpp::shutdown();
  return 0;
}
    • declare_parameter("name", "pickup") creates a parameter with its default value. The default also decides the type: 1.0 makes rate_hz a double, a vector of strings makes args a list of strings.
    • get_parameter("rate_hz").as_double() reads the current value. tick reads name and args every time it runs, so changing them takes effect on the next message with no extra code.
    • add_on_set_parameters_callback(...) registers a function that is called before a new value is accepted. It fills in a SetParametersResult: here a rate that is not positive is refused with a reason. An accepted new rate restarts the timer with the new period, because a timer does not notice a changed parameter by itself.
    • Like the publisher and the timer, the handle that add_on_set_parameters_callback returns is kept in a member (callback_handle_). It is the handle lifetime rule of A1 again: drop it and the callback is removed.
    • args is copied into a variable before the loop. get_parameter("args") returns a temporary object, and looping directly over something inside it uses memory that is already gone. When we wrote this lesson, that mistake crashed the program with std::length_error, not with a clear message.

    The listener (py/listener.pycpp/listener.cpp) is the A1 listener, subscribed to action.

  7. Start everything with a launch file

    Two announcers and a listener already means three terminals. This is code/04-parameters-launch/launch/announcers.launch.py:

    """Starts two announcers (with settings from config/announcers.yaml) and one listener.

    ros2 launch a4_params announcers.launch.py              Python programs
    ros2 launch a4_params announcers.launch.py lang:=cpp    C++ programs
"""
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration, PythonExpression
from launch_ros.actions import Node


def generate_launch_description():
    params_file = os.path.join(get_package_share_directory('a4_params'), 'config', 'announcers.yaml')
    lang = LaunchConfiguration('lang')

    def program(name):
        # Python programs were installed as name.py, C++ programs as name.
        return PythonExpression(["'", name, ".py' if '", lang, "' == 'py' else '", name, "'"])

    return LaunchDescription([
        DeclareLaunchArgument('lang', default_value='py', description="'py' or 'cpp': which programs to start"),
        Node(package='a4_params', executable=program('announcer'), name='planner_a',
             parameters=[params_file], output='screen'),
        Node(package='a4_params', executable=program('announcer'), name='planner_b',
             parameters=[params_file], output='screen'),
        Node(package='a4_params', executable=program('listener'), output='screen'),
    ])
    • generate_launch_description() is the function ros2 launch calls. It returns the list of things to start.
    • Each Node(...) starts one program: package and executable say which one, name is the node name (like -r __node:=), parameters takes the YAML file (or a Python dictionary), and output='screen' shows its log in this terminal.
    • The file is found through get_package_share_directory, the folder of an installed package where the build copied config/ and launch/, so it works from any folder.
    • DeclareLaunchArgument('lang', ...) gives the launch file an argument. program() uses it to choose between the Python programs (installed as announcer.py) and the C++ ones (announcer), so the same launch file serves both languages.

5. Exercise

Make planner_b announce pickup E once every two seconds without changing any Python or C++ code and without changing the launch file. Which file do you edit, and what must you do before the launch shows the change?

Answer

Edit config/announcers.yaml:

planner_b:
  ros__parameters:
    name: pickup
    args: [E]
    rate_hz: 0.5

A rate of 0.5 per second is one message every two seconds. Then run colcon build again: the launch file reads the copy in install/, and the build is what copies your edited file there. After source install/setup.bash (not needed again in a shell that was already sourced) the launch prints heard: pickup E every two seconds next to the two unstack F W lines per second. We ran exactly this.

6. Recap

  • A parameter is a named, typed setting of one node. It is declared with a default (which also fixes its type), read with get_parameter, and can be checked or refused by an on-set callback.
  • Outside the node: ros2 param list / get / describe / set / dump. Parameters are services underneath. Set values stay only while the node runs.
  • At start: --ros-args -p name:=value, --params-file file.yaml (top-level key = node name), and -r __node:=newname to rename the node.
  • A launch file is a Python function that returns the nodes to start, with names, parameters and launch arguments. ros2 launch pkg file.launch.py arg:=value starts them all, and Ctrl+C stops them all. --show-args lists the arguments.
  • ros2 run and ros2 launch use installed files: after editing a launch or YAML file, build again.
