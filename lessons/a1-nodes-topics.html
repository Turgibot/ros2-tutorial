A1 · Nodes and topics

Write two small programs (in Python or C++, your choice) that talk to each other through ROS 2, and learn to look at the conversation from outside.

1. Goal

At the end of this lesson you will have:

  • a talker program that publishes a message twice a second and a listener program that prints what it receives,
  • used ros2 node list, ros2 topic list, ros2 topic info, ros2 topic echo and ros2 topic hz to inspect them,
  • published a message by hand from the command line.

The robot arm is controlled with exactly these ideas: a program that reads joint positions and a program that sends commands are nodes that exchange messages on topics.

2. Concepts

Node, topic, message

  • A node is one running program that does one job and has a name (talker, listener). A robot system is many nodes.
  • A topic is a named channel (/chatter). Names start with /.
  • A message is one piece of data sent on a topic. Every topic carries one message type, such as std_msgs/msg/String, which has a single field string data.
  • A node that sends on a topic publishes. A node that receives subscribes. Several nodes can publish or subscribe to the same topic.

The publisher does not know who listens, and the listener does not know who talks. They only agree on the topic name and the message type. This is why you can start, stop and replace nodes one at a time.

  1. Read the talker

    This is code/01-nodes-topics/py/talker.py, the whole file:

    #!/usr/bin/env python3
"""Publishes a counter on /chatter twice a second."""
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class Talker(Node):
    def __init__(self):
        super().__init__('talker')
        self.pub = self.create_publisher(String, 'chatter', 10)
        self.count = 0
        self.create_timer(0.5, self.tick)   # call self.tick every 0.5 s

    def tick(self):
        msg = String()
        msg.data = f'hello {self.count}'
        self.pub.publish(msg)
        self.get_logger().info(f'sent: {msg.data}')
        self.count += 1


def main():
    rclpy.init()
    rclpy.spin(Talker())   # keep running and serving the timer until Ctrl+C


if __name__ == '__main__':
    main()
    • rclpy is the ROS 2 Python library. rclpy.init() connects the program to ROS 2.
    • super().__init__('talker') creates the node and gives it the name talker.
    • create_publisher(String, 'chatter', 10) declares: this node publishes String messages on the topic chatter (shown as /chatter). The 10 is how many unsent messages may wait in a queue if the receiver is slow.
    • create_timer(0.5, self.tick) calls tick every 0.5 seconds. Each call fills a message, publishes it and logs it.
    • rclpy.spin(...) keeps the program alive and runs the timer. Without it the program would end immediately.

    This is code/01-nodes-topics/cpp/src/talker.cpp, the whole file:

    // Publishes a counter on /chatter twice a second.
#include <chrono>
#include <memory>
#include <string>

#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

using namespace std::chrono_literals;

class Talker : public rclcpp::Node
{
public:
  Talker() : Node("talker")
  {
    pub_ = create_publisher<std_msgs::msg::String>("chatter", 10);
    timer_ = create_wall_timer(500ms, [this]() { tick(); });   // call tick every 0.5 s
  }

private:
  void tick()
  {
    std_msgs::msg::String msg;
    msg.data = "hello " + std::to_string(count_++);
    pub_->publish(msg);
    RCLCPP_INFO(get_logger(), "sent: %s", msg.data.c_str());
  }

  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr pub_;
  rclcpp::TimerBase::SharedPtr timer_;
  int count_ = 0;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<Talker>());   // keep running and serving the timer until Ctrl+C
  rclcpp::shutdown();
  return 0;
}
    • rclcpp is the ROS 2 C++ library. rclcpp::init(argc, argv) connects the program to ROS 2.
    • Our class Talker is a Node. Node("talker") gives it the name talker.
    • create_publisher<std_msgs::msg::String>("chatter", 10) declares: this node publishes String messages on the topic chatter (shown as /chatter). The 10 is how many unsent messages may wait in a queue if the receiver is slow. The message type comes from the header std_msgs/msg/string.hpp.
    • create_wall_timer(500ms, ...) calls tick every 500 milliseconds. The [this]() { tick(); } part is a small unnamed function (a lambda) that calls our method.
    • Why are pub_ and timer_ stored as members (the two lines at the bottom of the class)? create_publisher and create_wall_timer return a handle, and in C++ the publisher or timer lives only as long as something holds that handle. We tested it: with timer_ = removed, so that the handle is thrown away, the talker compiles and starts but never publishes anything. Keep every handle you create in a member variable. (Python does this for you inside the node, which is why talker.py does not store them.)
    • RCLCPP_INFO(get_logger(), "sent: %s", ...) prints a log line. %s is replaced by the text that follows.
    • rclcpp::spin(...) keeps the program alive and runs the timer. Without it the program would end immediately.

  2. Read the listener

    This is code/01-nodes-topics/py/listener.py:

    #!/usr/bin/env python3
"""Prints every message that arrives on /chatter."""
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class Listener(Node):
    def __init__(self):
        super().__init__('listener')
        self.create_subscription(String, 'chatter', self.on_message, 10)

    def on_message(self, msg):
        self.get_logger().info(f'heard: {msg.data}')


def main():
    rclpy.init()
    rclpy.spin(Listener())


if __name__ == '__main__':
    main()

    create_subscription(String, 'chatter', self.on_message, 10) says: call on_message every time a String arrives on chatter. The type and the topic name must match the publisher's. The listener has no loop of its own: spin waits, and ROS 2 calls on_message when data comes.

    This is code/01-nodes-topics/cpp/src/listener.cpp:

    // Prints every message that arrives on /chatter.
#include <memory>

#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

class Listener : public rclcpp::Node
{
public:
  Listener() : Node("listener")
  {
    sub_ = create_subscription<std_msgs::msg::String>(
      "chatter", 10,
      [this](const std_msgs::msg::String & msg) { RCLCPP_INFO(get_logger(), "heard: %s", msg.data.c_str()); });
  }

private:
  rclcpp::Subscription<std_msgs::msg::String>::SharedPtr sub_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<Listener>());
  rclcpp::shutdown();
  return 0;
}

    create_subscription<std_msgs::msg::String>("chatter", 10, ...) says: call the given function every time a String arrives on chatter. The function is a lambda that receives the message (msg) and logs it. The type and the topic name must match the publisher's. The listener has no loop of its own: spin waits, and ROS 2 calls the function when data comes.

    Optional: what is a "prefix"?

    A prefix is the root folder a package was installed into: the folder that holds that package's lib/, share/ and include/ folders. The word comes from the Unix idea of an installation prefix such as /usr. ros2 pkg prefix <package> prints it. Three examples from the course container:

    CommandPrefix printed
    ros2 pkg prefix rclcpp/opt/ros/jazzy
    ros2 pkg prefix kortex_bringup/opt/kortex_ws/install/kortex_bringup
    ros2 pkg prefix a1_nodes_topics/workspace/code/01-nodes-topics/cpp/install/a1_nodes_topics

    Ready-made (apt) packages all share one prefix, /opt/ros/jazzy. A package built with colcon gets its own prefix, install/<package>. ROS 2 finds prefixes through a list of folders called AMENT_PREFIX_PATH, which setup.bash files add to. So the command also answers "does this shell know the package at all?": Package not found means the package's setup.bash has not been sourced in this shell.

    Related: ros2 pkg prefix --share rclcpp prints the package's share folder, /opt/ros/jazzy/share/rclcpp, where its data files live.

  6. Watch the data and its rate

    container Still in terminal 3, print the messages as they pass:

    ros2 topic echo /chatter
    data: hello 12
---
data: hello 13
---
...

    Press Ctrl+C. echo is a third subscriber: it does not disturb the listener. Now measure how often messages arrive:

    ros2 topic hz /chatter
    average rate: 2.000
	min: 0.500s max: 0.500s std dev: 0.00028s window: 4

    2 messages per second, 0.5 s apart, matching create_timer(0.5, ...). Press Ctrl+C. topic hz is the first thing to check when a robot "does not respond": is data arriving, and how fast?

    You can also see the message definition behind a type:

    ros2 interface show std_msgs/msg/String
    # This was originally provided as an example message.
# It is deprecated as of Foxy
# It is recommended to create your own semantically meaningful message.
# However if you would like to continue using this please use the equivalent in example_msgs.

string data

    The last line is the whole message: one field named data of type string. (The comment says to prefer your own message types. We make one in lesson A2.)

  7. Publish from the command line

    container In terminal 3, send your own message to the same topic. The listener in terminal 2 cannot tell the difference between this and the talker:

    ros2 topic pub -r 1 /chatter std_msgs/msg/String "{data: typed by hand}"

    Look at terminal 2: lines heard: typed by hand appear among the hello N lines, once a second. -r 1 means one message per second. Press Ctrl+C in terminal 3 to stop. Here ros2 topic info /chatter would have shown 2 publishers.

  8. Stop one side

    Press Ctrl+C in terminal 1 (the talker). The listener keeps running and prints nothing: it is not an error, it just has nothing to receive. Start the talker again with the same command as in step 3, and the listener resumes by itself. Neither program had to know about the other's restart. Now press Ctrl+C in terminal 2 too, and type exit in all three terminals.

4. Check

You are done when all of these are true while both programs run:

  • ros2 node list shows /listener and /talker,
  • ros2 topic info /chatter shows Publisher count: 1 and Subscription count: 1,
  • ros2 topic hz /chatter reports an average rate of about 2.000.
Done when the listener prints heard: hello N lines and the three checks above agree.

5. Exercise

Change the timer in the talker (talker.pytalker.cpp) so it publishes 10 times per second. Compile again with colcon build and source install/setup.bash in the terminal where you run the talker. Restart the talker and run ros2 topic hz /chatter. What number do you expect? Then try this: with the talker running, run ros2 topic echo /nothing_here. What happens, and why?

Answer

10 messages per second means one every 0.1 s, so change the period to 0.1 s: self.create_timer(0.1, self.tick)create_wall_timer(100ms, ...). The rate is the inverse of the period: 1 / 0.1 s = 10 Hz.

average rate: 9.999
	min: 0.100s max: 0.100s std dev: 0.00014s window: 22

For the second part you see, after a few seconds:

WARNING: topic [/nothing_here] does not appear to be published yet
Could not determine the type for the passed topic

No node publishes /nothing_here, so ROS 2 cannot find a message type for it, and echo needs the type to subscribe. A mistyped topic name is one of the most common mistakes: ros2 topic list shows the names that really exist.

6. Recap

  • A node is a named running program. Nodes exchange data on topics, and every topic has one message type.
  • A node publishes with create_publisher and subscribes with create_subscription, giving a type, a topic name, a queue size (and, for the subscriber, a function to call). rclpy.spinrclcpp::spin keeps it running.
  • Publishers and subscribers do not know each other. Only the topic name and the type must match.
  • Python needs no build; C++ is compiled with colcon build and started with ros2 run after sourcing install/setup.bash.
  • Inspect with ros2 node list, ros2 topic list -t, ros2 topic info, ros2 topic echo, ros2 topic hz, and send with ros2 topic pub.
