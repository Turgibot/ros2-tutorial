D1 · Block poses to towers

From numbers to a sentence: a node that watches the blocks and says "B is on A, C is on D".

1. Goal

The simulator tells us where every block is: a position of three numbers. A planner, or a person, does not think in numbers: it thinks "A is on the table, C is on D". The step from numbers to such statements is the job of a world estimator, and its answer is the symbolic state of the world. At the end of this lesson you will have:

  • written the rule "X is on Y" as a test on two positions,
  • built towers from these relations, in Python and in C++,
  • published the result as a message on /towers, so any other node can use it,
  • moved blocks in Gazebo and watched the sentence change.
What was and was not run

Run in the course container, Gazebo headless, with the lab of C3 (no arm). Blocks were moved with the set_pose service of Gazebo, not by the arm (that comes in D2). The held case of the program (a block in the air) was seen only on a block that was falling, because nothing was holding one.

2. Concepts

Geometric state and symbolic state

The poses of C4 are the geometric state: four blocks, each with x, y, z. The symbolic state keeps only what matters to a plan: which block is on which. Two geometric states that differ by a centimetre are the same symbolic state. The symbolic state is small, easy to compare and to print, and a planner can reason with it. Part D uses it for the goals ("C on A") and Part E for recognising what a person is building.

The rule "X is on Y"

Blocks are cubes of side s = 0.05 m. If X rests on Y, then X is directly above Y, and the distance between their centres is one block height. Three tests, with tolerances to absorb small errors (a block placed by a gripper is never exactly in line):

dx = x_X − x_Y,   dy = y_X − y_Y,   dz = z_X − z_Y

X is on Y   when   |dx| < 0.03   and   |dy| < 0.03   and   |dz − 0.05| < 0.01

The tolerance in x and y is 3 cm, a bit more than half a block (2.5 cm): a block shifted by more than that would not rest on the other one. The tolerance in z is 1 cm. In C3 a resting block was at z = 0.325 to a micrometre, and the camera method of C4 was wrong by up to 5 mm; both fit in 1 cm.

A block that is on no other block is on the table if its height is the table's top plus half a block: |z − (0.30 + 0.025)| < 0.01. If it is neither on a block nor on the table, it is in the air: carried by a gripper, or falling. The program calls that held.

From relations to towers

A tower is a block on the table together with everything stacked on it. The program finds every block on the table, then follows the "is on" relation upwards: the block that is on it, the block that is on that one, and so on. A tower is written bottom to top: DCA is D on the table, C on D, A on C. Towers are separated by |, and sorted by their bottom block:

A | B | C | D        four blocks on the table
A | B | DC            C is on D
BA | DC                A is on B, C is on D

Publish a state, not a stream

The poses arrive 20 times a second per block, but the symbolic state changes only when a block is moved. The program publishes /towers only when the sentence changes, as a std_msgs/String. That raises one problem: a node that starts later would never receive the last message, and would know nothing until the next change. The fix is the quality of service transient local: the publisher keeps the last message, and gives it to every new subscriber. The program uses it (depth 1: only the last message matters).

  2. The estimator

    #!/usr/bin/env python3
"""The world estimator: turn the block poses into towers.

Reads /model/block_X/pose (ground truth from Gazebo) and publishes /towers (std_msgs/String), for example
"A | B | DC": three towers, A alone, B alone, and C standing on D. A block in the air (held by the gripper)
is reported on its own as "held: X"."""
import rclpy
from rclpy.node import Node
from rclpy.qos import DurabilityPolicy, QoSProfile
from geometry_msgs.msg import PoseStamped
from std_msgs.msg import String

BLOCKS = "ABCD"
SIZE = 0.05              # a block is a 5 cm cube
TABLE_Z = 0.30           # height of the table top
TOL_XY = 0.03            # "directly above": centres closer than 3 cm in x and in y
TOL_Z = 0.01             # heights are compared to within 1 cm


class Towers(Node):
    def __init__(self):
        super().__init__("towers")
        self.pos = {}
        self.last = None
        # "transient local": a program that starts later still receives the last message at once
        latched = QoSProfile(depth=1, durability=DurabilityPolicy.TRANSIENT_LOCAL)
        self.pub = self.create_publisher(String, "/towers", latched)
        for k in BLOCKS:
            self.create_subscription(PoseStamped, f"/model/block_{k}/pose",
                                     lambda msg, k=k: self.on_pose(k, msg), 10)

    def on_pose(self, k, msg):
        p = msg.pose.position
        self.pos[k] = (p.x, p.y, p.z)
        if len(self.pos) < len(BLOCKS):
            return
        text = describe(self.pos)
        if text != self.last:                  # publish only when something changed
            self.last = text
            self.pub.publish(String(data=text))
            self.get_logger().info(text)


def below(pos, k):
    """The block that k stands on, or None (k is on the table, or in the air)."""
    for j in BLOCKS:
        if j != k:
            dx, dy, dz = (pos[k][i] - pos[j][i] for i in range(3))
            if abs(dx) < TOL_XY and abs(dy) < TOL_XY and abs(dz - SIZE) < TOL_Z:
                return j
    return None


def on_table(pos, k):
    return abs(pos[k][2] - (TABLE_Z + SIZE / 2)) < TOL_Z


def describe(pos):
    above = {below(pos, k): k for k in BLOCKS if below(pos, k)}      # who is on top of whom
    towers, held = [], []
    for k in BLOCKS:
        if below(pos, k) is None:
            if on_table(pos, k):               # the bottom of a tower
                chain = k
                while chain[-1] in above:
                    chain += above[chain[-1]]
                towers.append(chain)
            else:
                held.append(k)
    text = " | ".join(sorted(towers))
    if held:
        text += "   held: " + " ".join(held)
    return text


def main():
    rclpy.init()
    rclpy.spin(Towers())


if __name__ == "__main__":
    main()
    // The world estimator: turn the block poses into towers.
// Reads /model/block_X/pose (ground truth from Gazebo) and publishes /towers (std_msgs/String), for example
// "A | B | DC": three towers, A alone, B alone, and C standing on D. A block in the air (held by the gripper)
// is reported on its own as "held: X".
#include <algorithm>
#include <array>
#include <cmath>
#include <map>
#include <memory>
#include <string>
#include <vector>
#include <geometry_msgs/msg/pose_stamped.hpp>
#include <rclcpp/rclcpp.hpp>
#include <std_msgs/msg/string.hpp>

const std::string BLOCKS = "ABCD";
const double SIZE = 0.05;      // a block is a 5 cm cube
const double TABLE_Z = 0.30;   // height of the table top
const double TOL_XY = 0.03;    // "directly above": centres closer than 3 cm in x and in y
const double TOL_Z = 0.01;     // heights are compared to within 1 cm

using Pos = std::array<double, 3>;

// The block that k stands on, or 0 (k is on the table, or in the air).
char below(const std::map<char, Pos> &pos, char k) {
  for (char j : BLOCKS) {
    if (j == k) continue;
    double dx = pos.at(k)[0] - pos.at(j)[0], dy = pos.at(k)[1] - pos.at(j)[1], dz = pos.at(k)[2] - pos.at(j)[2];
    if (std::fabs(dx) < TOL_XY && std::fabs(dy) < TOL_XY && std::fabs(dz - SIZE) < TOL_Z) return j;
  }
  return 0;
}

bool on_table(const std::map<char, Pos> &pos, char k) {
  return std::fabs(pos.at(k)[2] - (TABLE_Z + SIZE / 2)) < TOL_Z;
}

std::string describe(const std::map<char, Pos> &pos) {
  std::map<char, char> above;                      // who is on top of whom
  for (char k : BLOCKS) if (below(pos, k)) above[below(pos, k)] = k;
  std::vector<std::string> towers;
  std::string held;
  for (char k : BLOCKS) {
    if (below(pos, k)) continue;
    if (on_table(pos, k)) {                        // the bottom of a tower
      std::string chain(1, k);
      while (above.count(chain.back())) chain += above[chain.back()];
      towers.push_back(chain);
    } else {
      held += std::string(" ") + k;
    }
  }
  std::sort(towers.begin(), towers.end());
  std::string text;
  for (size_t i = 0; i < towers.size(); ++i) text += (i ? " | " : "") + towers[i];
  if (!held.empty()) text += "   held:" + held;
  return text;
}

class Towers : public rclcpp::Node {
public:
  Towers() : Node("towers") {
    // "transient local": a program that starts later still receives the last message at once
    pub_ = create_publisher<std_msgs::msg::String>("/towers", rclcpp::QoS(1).transient_local());
    for (char k : BLOCKS) {
      subs_.push_back(create_subscription<geometry_msgs::msg::PoseStamped>(
          std::string("/model/block_") + k + "/pose", 10,
          [this, k](const geometry_msgs::msg::PoseStamped::SharedPtr msg) { on_pose(k, *msg); }));
    }
  }

private:
  void on_pose(char k, const geometry_msgs::msg::PoseStamped &msg) {
    const auto &p = msg.pose.position;
    pos_[k] = {p.x, p.y, p.z};
    if (pos_.size() < BLOCKS.size()) return;
    std::string text = describe(pos_);
    if (text != last_) {                           // publish only when something changed
      last_ = text;
      std_msgs::msg::String out;
      out.data = text;
      pub_->publish(out);
      RCLCPP_INFO(get_logger(), "%s", text.c_str());
    }
  }

  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr pub_;
  std::vector<rclcpp::Subscription<geometry_msgs::msg::PoseStamped>::SharedPtr> subs_;
  std::map<char, Pos> pos_;
  std::string last_;
};

int main(int argc, char **argv) {
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<Towers>());
  rclcpp::shutdown();
  return 0;
}
    • below(k) is the rule of the Concepts: it looks for a block j that k stands on, or none.
    • describe builds a map "who is on top of whom", starts a tower at each block that is on the table, and follows the map upwards.
    • The node subscribes to the four pose topics of C3, keeps the latest position of each, and every time a pose arrives, recomputes the sentence. It publishes and logs it only if it is different from the last one.

  5. A late subscriber

    This echo started long after the last change and still got the answer at once: the transient-local quality of service at work. Without it, --once would have waited for the next change. Check the setting of the publisher:

    ros2 topic info /towers -v | grep Durability
      Durability: TRANSIENT_LOCAL

    (That is the publisher's setting; echo adapts its own to it.) In the test run, a late echo also got the last sentence from the C++ estimator after the Python one was stopped.

  • The estimator printed A | B | C | D at the start.
  • After C was moved onto D, it printed A | B | DC, and after A onto B, BA | DC.
  • One line per change; none while nothing moves.
  • ros2 topic echo /towers --once printed the last sentence immediately.

6. Recap

  • Geometric state (poses) versus symbolic state (which block is on which). The estimator turns the first into the second.
  • "X is on Y": centres within 3 cm in x and y, and one block height (5 cm ± 1 cm) apart in z. "On the table": z = 0.325 ± 0.01. Otherwise the block is in the air.
  • Towers: start at the blocks on the table, follow "is on" upwards; written bottom to top, e.g. DCA.
  • Publish the state only when it changes, with transient local QoS so that late subscribers get the last state at once.
  • Not tested here: a block carried by a gripper (D2), more than four blocks, noisy poses from the camera instead of the ground truth.
