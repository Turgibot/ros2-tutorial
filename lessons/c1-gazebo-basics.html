C1 · Gazebo basics

A physics simulator of your own: a world in a file, a box that falls, and a bridge that brings its state into ROS 2.

1. Goal

Until now the arm was "fake hardware": a program that repeats every command back as if it had moved. Nothing has mass, nothing can fall, and nothing collides. Gazebo is a physics simulator: it computes forces, contacts and motion, step by step. The digital twin of the course (Part C and D) is a Gen3 arm in Gazebo.

Before the arm, this lesson uses the simplest possible world, so that every piece is visible. At the end you will have:

  • written a world file (SDF) with a ground and a falling box,
  • run Gazebo without a window (headless) and paused,
  • pressed play, pause and step from the command line,
  • bridged the box's pose and the clock into ROS 2 with ros_gz_bridge,
  • and checked the simulator against a formula from school physics.
What was and was not run

Everything on this page was run in the course container, with Gazebo running headless (no window). The Gazebo window (gz sim -g) was started and stayed up for 12 s with no error, but nobody looked at it, so the lesson has no screenshot of it, and says nothing about how it looks.

2. Concepts

Gazebo, gz and the version

The simulator in the image is Gazebo Harmonic: the command is gz, and the program is gz sim (version 8.15 here). Older tutorials talk about "Gazebo Classic" and the command gazebo: that is a different program, and its files do not work here.

A world is a file

A world is an XML file in the SDF format (Simulation Description Format). It lists the physics settings, the lights, and the models. A model is made of links (rigid bodies) and joints. A link has three parts, and they are separate on purpose:

  • inertial: the mass and the inertia (how hard it is to push and to spin),
  • collision: the shape used for contacts (as simple as possible, for speed),
  • visual: the shape and the colour you see (as nice as you like).

This is the same idea as the URDF of B1, with one difference: URDF describes a robot, SDF describes a whole world.

Systems (plugins)

An empty SDF world does nothing: not even physics. Each ability is a system plugin that you list in the world: Physics moves the bodies, UserCommands lets you create and move models and control time, SceneBroadcaster tells a window what to draw. A system can also be placed inside a model: below, one makes the box publish its pose.

Server and window

gz sim is two programs: the server (the physics, -s) and the GUI (the window, -g). By default one command starts both. Here only the server runs, and the GUI can join later from any terminal. This matters because the course containers often run without a display.

Two message systems, and a bridge

Gazebo does not use ROS 2 inside. It has its own topics and services (gz topic, gz service) with its own message types (gz.msgs.Pose). The program ros_gz_bridge copies a chosen topic from one side to the other, converting the type. You tell it with a string:

/model/box/pose @ geometry_msgs/msg/PoseStamped [ gz.msgs.Pose
  topic name         ROS 2 type                    ^   Gazebo type
                                                   '-- "[": from Gazebo to ROS 2   "]": ROS 2 to Gazebo   "@": both ways

Simulated time

Simulated time is not wall-clock time. Gazebo advances it in steps of max_step_size (1 ms here), and publishes it on /clock. When paused, it stands still. ROS 2 nodes can follow it with the parameter use_sim_time:=true; the arm in C2 does.

  2. Read the world

    <?xml version="1.0"?>
<sdf version="1.9">
  <world name="hello">
    <physics name="1ms" type="ode">
      <max_step_size>0.001</max_step_size>
      <real_time_factor>1.0</real_time_factor>
    </physics>
    <plugin filename="gz-sim-physics-system" name="gz::sim::systems::Physics"/>
    <plugin filename="gz-sim-user-commands-system" name="gz::sim::systems::UserCommands"/>
    <plugin filename="gz-sim-scene-broadcaster-system" name="gz::sim::systems::SceneBroadcaster"/>
    <gravity>0 0 -9.81</gravity>

    <light type="directional" name="sun">
      <cast_shadows>true</cast_shadows>
      <pose>0 0 10 0 0 0</pose>
      <direction>-0.5 0.1 -0.9</direction>
      <diffuse>0.9 0.9 0.9 1</diffuse>
    </light>

    <model name="ground">
      <static>true</static>
      <link name="link">
        <collision name="collision">
          <geometry><plane><normal>0 0 1</normal><size>10 10</size></plane></geometry>
        </collision>
        <visual name="visual">
          <geometry><plane><normal>0 0 1</normal><size>10 10</size></plane></geometry>
          <material><ambient>0.8 0.8 0.8 1</ambient><diffuse>0.8 0.8 0.8 1</diffuse></material>
        </visual>
      </link>
    </model>

    <model name="box">
      <pose>0 0 1.0 0 0 0</pose>
      <!-- publish this model's pose on /model/box/pose -->
      <plugin filename="gz-sim-pose-publisher-system" name="gz::sim::systems::PosePublisher">
        <publish_model_pose>true</publish_model_pose>
        <publish_link_pose>false</publish_link_pose>
        <update_frequency>50</update_frequency>
      </plugin>
      <link name="link">
        <inertial>
          <mass>1.0</mass>
          <inertia><ixx>0.0167</ixx><iyy>0.0167</iyy><izz>0.0167</izz><ixy>0</ixy><ixz>0</ixz><iyz>0</iyz></inertia>
        </inertial>
        <collision name="collision"><geometry><box><size>0.2 0.2 0.2</size></box></geometry></collision>
        <visual name="visual">
          <geometry><box><size>0.2 0.2 0.2</size></box></geometry>
          <material><ambient>0.8 0.1 0.1 1</ambient><diffuse>0.8 0.1 0.1 1</diffuse></material>
        </visual>
      </link>
    </model>
  </world>
</sdf>
    • physics: a step of 1 ms, run at real-time speed (real_time_factor 1). The physics engine is ODE.
    • three plugin lines, the systems from the Concepts. Without the first, nothing would move.
    • ground is static: it never moves, and it has a collision and a visual but no mass. Its shape is a plane, 10 m by 10 m.
    • box starts 1 m above the ground. It is a cube of 0.2 m with a mass of 1 kg. Its inertia is 0.0167 kg·m² around each axis: for a cube, m·s²/6 = 1 × 0.2² / 6.
    • the PosePublisher plugin inside box publishes the pose of the model, 50 times per second of simulated time, on /model/box/pose.

  3. Start Gazebo and the bridge

    The launch file starts the server on the world file and the bridge for three things: the clock, the box pose, and the service that controls time. container T1:

    """Gazebo server with the hello world (paused), plus the ros_gz bridge for /clock, the box pose (PoseStamped) and the world-control service."""
import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, ExecuteProcess
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def generate_launch_description():
    default_world = os.path.join(get_package_share_directory("c1_gazebo"), "worlds", "hello.sdf")
    world = DeclareLaunchArgument("world_file", default_value=default_world)
    # -s: server only (no window). No -r, so the world starts paused.
    gz = ExecuteProcess(cmd=["gz", "sim", "-s", LaunchConfiguration("world_file")], output="screen")
    bridge = Node(
        package="ros_gz_bridge", executable="parameter_bridge", output="screen",
        arguments=[
            "/clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock",
            "/model/box/pose@geometry_msgs/msg/PoseStamped[gz.msgs.Pose",
            "/world/hello/control@ros_gz_interfaces/srv/ControlWorld",
        ])
    return LaunchDescription([world, gz, bridge])
    ros2 launch c1_gazebo hello.launch.py

    The bridge prints one line per bridged item (Creating GZ->ROS Bridge for the clock and the pose, Creating ROS->GZ service bridge for the control service). There is no window and no more output: the world is paused, because the launch file did not pass -r (run) to gz sim.

  5. Watch the box fall

    Here is the program that watches the box. It reads the bridged pose and prints the height every 0.1 s of simulated time, and when the box has landed.

    #!/usr/bin/env python3
"""Watch the pose of the model "box" that Gazebo publishes (bridged to ROS as geometry_msgs/PoseStamped)
and print its height every 0.1 s of simulated time, and the moment it lands."""
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import PoseStamped

GROUND_Z = 0.1        # the box is 0.2 m tall, so its centre is 0.1 m above the ground when it rests
START_Z = 1.0         # where the world file puts the box


class BoxHeight(Node):
    def __init__(self):
        super().__init__("box_height")
        self.last_print = -1.0
        self.landed = False
        self.create_subscription(PoseStamped, "/model/box/pose", self.on_pose, 10)

    def on_pose(self, msg):
        t = msg.header.stamp.sec + msg.header.stamp.nanosec * 1e-9
        z = msg.pose.position.z
        if t - self.last_print >= 0.1:
            self.last_print = t
            self.get_logger().info(f"t = {t:5.2f} s   z = {z:.3f} m")
        if not self.landed and z <= GROUND_Z + 0.001:
            self.landed = True
            self.get_logger().info(f"landed after {t:.3f} s of simulated time")


def main():
    rclpy.init()
    rclpy.spin(BoxHeight())


if __name__ == "__main__":
    main()
    // Watch the pose of the model "box" that Gazebo publishes (bridged to ROS as geometry_msgs/PoseStamped)
// and print its height every 0.1 s of simulated time, and the moment it lands.
#include <cstdio>
#include <memory>
#include <rclcpp/rclcpp.hpp>
#include <geometry_msgs/msg/pose_stamped.hpp>

const double GROUND_Z = 0.1;   // the box is 0.2 m tall, so its centre is 0.1 m above the ground when it rests

class BoxHeight : public rclcpp::Node {
public:
  BoxHeight() : Node("box_height") {
    sub_ = create_subscription<geometry_msgs::msg::PoseStamped>(
        "/model/box/pose", 10,
        [this](const geometry_msgs::msg::PoseStamped::SharedPtr msg) { on_pose(*msg); });
  }

private:
  void on_pose(const geometry_msgs::msg::PoseStamped &msg) {
    double t = msg.header.stamp.sec + msg.header.stamp.nanosec * 1e-9;
    double z = msg.pose.position.z;
    if (t - last_print_ >= 0.1) {
      last_print_ = t;
      RCLCPP_INFO(get_logger(), "t = %5.2f s   z = %.3f m", t, z);
    }
    if (!landed_ && z <= GROUND_Z + 0.001) {
      landed_ = true;
      RCLCPP_INFO(get_logger(), "landed after %.3f s of simulated time", t);
    }
  }

  rclcpp::Subscription<geometry_msgs::msg::PoseStamped>::SharedPtr sub_;
  double last_print_ = -1.0;
  bool landed_ = false;
};

int main(int argc, char **argv) {
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<BoxHeight>());
  rclcpp::shutdown();
  return 0;
}

  6. Check the physics with a formula

    A body falling from rest covers h = ½·g·t². The box centre falls from 1.0 m to 0.1 m, so h = 0.9 m and

    t = sqrt( 2·h / g ) = sqrt( 2 × 0.9 / 9.81 ) = 0.428 s

    The program says the box was at rest height by 0.44 s. Its samples come every 0.02 s (50 Hz), and 0.44 is the first sample after 0.428. The heights also fit: at t = 0.34 s the formula gives 1.0 − ½ × 9.81 × 0.34² = 0.433 m, and the program printed 0.431. The simulator and the formula agree: this is what "the twin follows physics" means.

  7. Pause, step, and the clock

    The world has been running since you pressed play, and the clock keeps counting. Check how fast, in T2:

    ros2 topic hz /clock
    average rate: 1000.201
	min: 0.001s max: 0.001s std dev: 0.00002s window: 1002

    1000 messages per second, one per 1 ms step: simulated time runs at the speed of real time. Press Ctrl+C, then pause, and read the clock twice:

    ros2 service call /world/hello/control ros_gz_interfaces/srv/ControlWorld "{world_control: {pause: true}}"
ros2 topic echo /clock --once
ros2 topic echo /clock --once

    Both reads show the same time (7.685 s in the test run; yours differs: it is however long the world ran). Now step 100 times (100 × 1 ms = 0.1 s) while paused:

    ros2 service call /world/hello/control ros_gz_interfaces/srv/ControlWorld "{world_control: {pause: true, multi_step: 100}}"
ros2 topic echo /clock --once

    The clock moved forward by exactly 0.1 s (7.685 s to 7.785 s in the test run) and stopped again. Stepping is how a program can run the simulation at its own pace, for example to run it faster than real time or one control cycle at a time.

    Careful: always say pause: true with a step

    A WorldControl message has a field pause that is false unless you set it. {multi_step: 100} alone steps and then plays: the world runs on and the clock races away. This was tested: three such calls moved the clock by about 2 s each. Write pause: true, multi_step: 100.

    The same from Gazebo's own tools (no ROS 2)

    container T2. The bridge is not needed for these:

    gz service -s /world/hello/control --reqtype gz.msgs.WorldControl --reptype gz.msgs.Boolean --timeout 2000 --req 'pause: true'
gz topic -e -t /world/hello/stats -n 1
gz topic -l

    The first pauses the world (data: true means it worked). The second prints one statistics message: the simulated time, the real time, the step size and the real_time_factor (1.0 here: simulated time passed at the same rate as real time), and paused. The third lists all Gazebo topics, including the ones the bridge does not carry.

    No "reset"

    The control service also has a reset field. It was tried here ({reset: {all: true}}) and did not work as expected: afterwards the clock was not back at 0 and the box pose was no longer published. To run again, stop the launch in T1 (Ctrl+C) and start it again.

    Open the Gazebo window on a running server

    This needs a display (the container run script passes yours through). container T2:

  • T2 listed the models ground and box, and the ROS 2 topics /clock and /model/box/pose.

5. Exercise

Predict, then try. (1) The box starts at 2 m instead of 1 m: when does it land? (2) The box weighs 10 kg instead of 1 kg: when does it land? Make a copy of the world, change it, and start the launch with world_file:= and the path of your copy.

Answer

(1) The centre falls 1.9 m: t = √(2 × 1.9 / 9.81) = 0.622 s. (2) Mass does not matter: gravity accelerates all bodies the same (there is no air in the world), so it lands at the same time as the 1 kg box. Both were run: the 2 m box printed landed after 0.640 s (the first 0.02 s sample after 0.622 s) and the 10 kg box landed after 0.440 s.

sed 's#<pose>0 0 1.0 0 0 0</pose>#<pose>0 0 2.0 0 0 0</pose>#' worlds/hello.sdf > /tmp/w2.sdf
ros2 launch c1_gazebo hello.launch.py world_file:=/tmp/w2.sdf

(For the second, change <mass>1.0</mass> to 10.0 the same way. The inertia stays as it is; it only matters for rotation.)

6. Recap

  • Gazebo Harmonic: gz sim, a server (-s, the physics) and a GUI (-g). The server runs fine without a display.
  • A world is an SDF file: physics settings, system plugins, models made of links with inertial, collision and visual parts.
  • Gazebo has its own topics and services; ros_gz_bridge copies chosen ones to ROS 2 with the string topic@RosType[GzType.
  • Simulated time is on /clock, advances in 1 ms steps, and can be paused, played and stepped through the /world/hello/control service. With a step, always send pause: true.
  • The simulator agrees with t = √(2h/g), and the mass of a falling body does not change when it lands.
  • Not tested: reset, the Gazebo window's look, the sensors (a camera needs a renderer: C4).
